# Pulsar mobile app (Android; iOS aspirational)

Android app for Pulsar — Tauri 2 mobile, "Path A": **transparent webview over a
native video surface**. See the umbrella `../CLAUDE.md` for the product.

**Reality check vs the README:** the phone is a full **host too**, not just a
client — `mobile/src/host.rs` accepts inbound sessions; `HostEncoder.kt` does
MediaProjection capture + MediaCodec encode; `PulsarA11yService.kt` injects the
remote peer's gestures (accessibility service + SYSTEM_ALERT_WINDOW). **iOS does
not exist yet** (no `gen/apple/`, no Swift — only a plugin binding stub + icons).
AndroidTV is supported (leanback launcher + `gamepad-nav.js` D-pad navigation).

## Layout

- `mobile/` — the Tauri app crate (`pulsar-mobile`). `src/`: client.rs (2k LOC),
  host.rs, net.rs, rtp.rs, datachan.rs, session_cmds.rs, relay_cmds.rs
  (on-device local relay: `start/stop/local_relay_status`), config, identity.
- `mobile/ui/` — **static** webview UI, plain ES modules, no bundler
  (`frontendDist: "ui"`). i18n: `ui/js/i18n/{en,tr,ru,kk}.js`.
- `crates/tauri-plugin-pulsar-video/` — the native surface plugin.
  `PulsarVideoPlugin.kt` (~2.8k lines) is the center of gravity.
- Deps: `pulsar-core` + `pulsar-relay` as **git deps**.

## Critical gotchas

- **`mobile/gen/android/` is GITIGNORED** — regenerated by `tauri android init`.
  Any hand-edit there (MainActivity, AndroidManifest) is NOT in version control
  and WILL be wiped. This already ate the MulticastLock +
  `CHANGE_WIFI_MULTICAST_STATE` fix LAN discovery receive needs — comments in
  `net.rs`/`client.rs` claiming "acquired in MainActivity" are stale. Durable
  Android changes go in the plugin (`android/`) or the patch scripts
  (`mobile/scripts/patch-android-*.py`).
- **Renderer:** SurfaceView is the default everywhere (Moonlight-style).
  TextureView (needed on the emulator — SurfaceView composites green there, and
  the only path where pinch-zoom's Matrix transform applies) is an adb opt-in:
  `adb shell setprop debug.pulsar.tv 1`.
- **JS must invoke plugin commands in snake_case** (camelCase → "command not
  found"); command must be in `build.rs` COMMANDS + `permissions/default.toml`;
  `touch src/lib.rs` to re-bake the ACL.
- **Dead code warning:** `ui/js/session/{input,split,gamepad}.js` (~3.6k lines)
  are imported by NOTHING. Live touch/gesture code is `ui/js/app.js`; live
  session modules are only what `app.js` dynamically imports. Check imports
  before editing a session module.
- Many ui modules inject CSS via JS template literals — a stray backtick/`${`
  breaks the whole module silently (import `.catch` swallows it). Run
  `node --check` after editing.

## Develop

```bash
cd mobile && bun install
bun run tauri android dev        # emulator/device (SDK+NDK; see project memory)
cargo check -p pulsar-mobile     # host compile-check, no device toolchain
```

Standalone debug APK: `tauri android build --debug`, install the **universal**
variant (`arm64`-only can carry a stale cached devUrl). `tauri android dev`
always bakes a live devUrl — the APK breaks when you kill the dev process.

Releases: build-first — semantic-release dry-runs the version, both APKs are built
with it (`--config '{"version":…}'`, tauri.conf.json is never rewritten) and
verified, THEN the tag + release is cut with the APKs attached. Two APKs:
`Pulsar-android.apk` has the accessibility service STRIPPED (Play Protect blocks
browser installs of apps that declare one — `scripts/patch-android-no-a11y.py`;
the plugin's `a11yAvailable` tells the host screen), `Pulsar-android-hostcontrol.apk`
keeps it (adb install). The launcher icon must be re-branded after
`tauri android init` (`tauri icon app-icon.png`) or the APK ships Tauri's icon.
